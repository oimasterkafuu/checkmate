Checkmate!! 机器人开发协议

Checkmate!! 欢迎机器人开发。我们不仅提供文档，还提供两个示例。

1. 连接与鉴权

Socket 地址 与站点同源，Socket.IO 默认路径 /socket.io/。
transport 服务端支持 websocket 与 polling。
鉴权字段 握手优先读取 auth.token（JWT），否则回退读取 Cookie 里的 auth_token。
鉴权失败 连接会被拒绝（客户端会收到 connect_error）。
身份标识 连接后服务器会下发 set_id（字符串），值为当前 socket id 的 MD5。后续在 init_map.player_ids 与 update.kills 中都用这个 ID。 
// JS 连接示例
const socket = io(BOT_SERVER, {
  transports: ['websocket', 'polling'],
  auth: { token: process.env.BOT_TOKEN }
});

2. 房间阶段协议（开局前）

2.1 Client → Server

join_game_room { room: string }。房间号服务端限制长度 1..15；建议只使用 [0-9A-Za-z_-]。
change_team { team: number }。0 表示观战；1..16 表示参赛/队伍号。非组队模式下，非 0 会被规整为参赛。
change_ready { ready: boolean }。仅参赛者有效，且仅在房间未开局时生效。
change_game_conf 可选字段 patch：speed（0.5~4）、allow_team（bool）、 map_mode（random|maze|archipelago）、map_token（最长 32）。 仅房主可改。

2.2 Server → Client

room_update 房间状态快照： { speed, allow_team, map_token, map_mode, in_game, players, ready, need }。
room_update.players[] 每项为 { sid, uid, team, ready }： sid 为该玩家 socket id 的 MD5；uid 为用户名；team 为 0(观战) 或队伍号；ready 为准备状态。
ready / need 当前已准备人数 / 开局所需人数。need <= 1 时不会开局。
starting {}。满足开局条件后广播，表示即将进入对局。
chat_message 聊天消息：{ sender, color, text, team }。color=0 时通常是系统消息。

3. 对局阶段协议（开局后）

3.1 开局事件

init_map { n, m, player_ids, general }。 n/m 为行列；player_ids 是所有玩家 MD5 SID； general=[x,y] 是你自己的主城坐标。观战者一般为 [-1,-1]。
玩家编号映射 令 self_id = set_id，在 player_ids 中查找位置： 下标从 0 开始，对应游戏 owner id = index + 1。

3.2 回合事件 update

整体结构 { grid_type, army_cnt, lst_move, leaderboard, turn, kills, surrender_progress, game_end, is_diff, replay? }
turn 半回合计数（前端显示为 Math.floor(turn/2)）。速度 1x 时 tick 约 500ms。
is_diff = false grid_type 与 army_cnt 都是长度 n*m 的全量数组，按行优先展开。
is_diff = true grid_type/army_cnt 均为 index-value 对： [idx0, val0, idx1, val1, ...]。 idx = x * m + y（行优先）。机器人需要在本地缓存全图并增量合并。
lst_move { x, y, dx, dy, half }。表示服务器已执行的最近行动（用于客户端队列确认）。 无动作时为 {-1,-1,-1,-1,false}。
leaderboard[] 每项结构：{ team, uid, army, land, class_, dead, id }。 class_ 可为 ''、'afk'、'dead'。
kills Record<sid_md5, killer_name>。当你被击败时，键为你的 set_id。
surrender_progress Record<owner_id, ratio>，ratio 范围 0..1，用于渲染投降衰减效果。
game_end true 表示该帧为终局帧。
replay 可选字符串，仅在终局附近出现，表示回放 ID。

3.3 Tile 编码（grid_type）

0..49 普通地块，owner id = code（0 表示中立空地）。
50..99 城市，owner id = code - 50；50 为中立城市。
100..149 将军（主城），owner id = code - 100。
150..199 沼泽，owner id = code - 150。
200 可见空地（中立）。
201 可见山脉（不可通行）。
202 战争迷雾中的未知地块。
203 战争迷雾中的障碍/特殊地块（如山脉或城市类障碍，具体类型被隐藏）。
204 可见中立沼泽。
205 迷雾中的沼泽。

army_cnt 与 grid_type 同维度。迷雾格兵力通常为 0。

4. 对局内可发送操作

attack { x, y, dx, dy, half }。坐标均为 [row, col]。 (x,y) 是起点，(dx,dy) 是目标，要求四邻接；half=true 表示 50% 出兵。
clear_queue 清空当前玩家待执行操作队列。
pop_queue 删除队尾一条待执行操作。
send_message { text, team }。team=true 表示队伍频道。
surrender 投降并转观战。
return_room / leave 退出对局返回房间。服务端会回 left。

5. 增量帧合并示例

// 已知 n, m 和本地 fullGrid/fullArmy（长度 n*m）
function applyUpdate(frame) {
  if (frame.is_diff) {
    for (let i = 0; i < frame.grid_type.length; i += 2) {
      fullGrid[frame.grid_type[i]] = frame.grid_type[i + 1];
    }
    for (let i = 0; i < frame.army_cnt.length; i += 2) {
      fullArmy[frame.army_cnt[i]] = frame.army_cnt[i + 1];
    }
  } else {
    fullGrid = frame.grid_type.slice();
    fullArmy = frame.army_cnt.slice();
  }
}
提示：
  • 任何时刻都维护一份全量缓存，避免只依赖 diff 帧。
  • 收到 is_diff=false 全量帧时，用它重置本地状态。
